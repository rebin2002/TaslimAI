# Release Governance Acceptance Evidence

## Purpose and boundary

This document defines the evidence packet for the `main` release gate. It complements, but does not replace, repository administration. The repository-controlled evidence is generated by `scripts/release-governance-evidence.sh`; it never changes GitHub settings, merges a pull request, deploys, applies a migration, calls a provider, charges a customer, or reads secrets.

The remote protection/ruleset acceptance remains tracked by [issue #283](https://github.com/rebin2002/TaslimAI/issues/283). PR #275 is a separate integration candidate and remains subject to explicit human merge/release authorization; green CI is not authorization.

## Repository-controlled acceptance evidence

The governance evidence script must report all of the following:

- Pull requests run the normal CI workflow.
- Pull requests run release-evidence checks.
- The CI workflow exposes stable contexts for `Frontend checks`, `API integration tests`, `Browser E2E`, and `Deployment smoke helper contracts`.
- The release-evidence workflow exposes `Release evidence and safety contract`.
- Workflow permissions are limited to `contents: read`.
- Every referenced GitHub Action is pinned to a full commit SHA and retains a version comment.
- No workflow uses `pull_request_target`.
- The evidence explicitly records that remote main protection and ruleset state still require administrator attestation.
- The evidence explicitly records that PR #275 cannot be merged or released automatically.

Run locally from a full checkout:

```bash
bash scripts/release-governance-evidence.test.sh
bash scripts/release-governance-evidence.sh /tmp/taslim-release-governance-evidence.json
bash scripts/api-health-smoke.test.sh
```

The generated JSON is intentionally secret-free and records only workflow contracts, source identity, required acceptance criteria, and safety boundaries. It is not a claim that GitHub main is protected.

## Required administrator acceptance for issue #283

After an authorized repository administrator applies the least-privileged ruleset, record the exact ruleset or protection ID and capture read-only evidence for:

1. `main` is protected and direct pushes, force pushes, and branch deletion are disallowed.
2. Pull requests, required review approval, review resolution, and current-head required checks are enforced.
3. The exact stable check contexts are required: `Taslim CI / Frontend checks`, `Taslim CI / API integration tests`, `Taslim CI / Browser E2E`, `Taslim CI / Deployment smoke helper contracts`, `Production container smoke / Build production container and health smoke`, and `Taslim Release Evidence / Release evidence and safety contract`, as applicable to the final workflow names.
4. Intentionally skipped stacked-PR jobs are not made required for branches where they do not run.
5. Bypass actors are documented and least-privileged; bypass does not authorize release of PR #275.
6. A disposable test PR with a deliberately failing required check is rejected, while an approved green path succeeds.
7. The final evidence records the protected ref, rule ID, required contexts, reviewer requirements, bypass actors, and verification timestamps.

Do not mark this acceptance complete from local CI alone. A green PR demonstrates code health, not repository governance.

## Reliability contract

The production readiness smoke helper now requires both `database` and `storage` checks to be present, marked required, and reported `available`. This prevents a malformed or regressed readiness response from being treated as launch-ready merely because the database probe passes. The helper remains read-only and uses no production mutation or provider call.
