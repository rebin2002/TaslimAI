# Movie Studio Remaining-Gap Report — 2026-10-03

## Scope and safety boundary

This report covers the backend/provider closure wave on `main` at commit `6fa43cb`.
No paid provider call, purchase, customer charge, secret, production deployment, or
destructive database operation was used. All tests use deterministic fakes or in-process
configuration values.

## A. Code gaps still remaining

1. **Sound effects and ambience remain unavailable.** `IMovieSoundProvider` has only the
   deterministic fake and unavailable implementation in production. The generic
   `IMusicGenerationProvider` contract describes music generation and cannot be reused as
   SFX/ambience without changing the product semantics, output taxonomy, duration behavior,
   and provenance contract.
2. **Soundtrack media execution remains unavailable.** `MovieSoundtrackService.SubmitMediaAsync`
   now reaches `IMovieSoundtrackMediaService.SubmitAsync`, but the production registration is
   still fail-closed. The current seam returns an operation ID only; it does not own a durable
   generation job, provider polling/callback state, bounded audio retrieval, private
   `StoredFile` publication, `Asset` creation, or soundtrack-version provenance capture.
   Calling a generic music provider here would drop the generated bytes or bypass those
   boundaries, so no adapter was invented.
3. **The optional generic video adapter is not Movie's canonical provider path.**
   `IVideoGenerationAdapter` has its own normalized asynchronous execution service and an
   unavailable production registration. Movie Studio continues to use `IMovieVideoProvider`,
   `MovieVideoProviderRegistry`, and the persisted Movie execution state. No bridge was added
   because there is no verified vendor-neutral contract that would add value without
   duplicating `RunwayMovieVideoProvider` or `ManusMovieVideoProvider`.

## B. Provider credentials/contracts required

1. **Movie dialogue voice:** `MovieDialogueVoiceProviderAdapter` now maps Movie dialogue to
   the existing `IVoiceGenerationProvider` contract and preserves returned content type,
   format, duration, model/usage evidence, cost basis, and safe metadata. Production still
   requires `MovieDialogueVoice:Enabled=true`, a matching `VoiceGeneration` provider, complete
   provider credentials, a valid HTTPS endpoint, and a separately approved commercial account.
   Defaults remain disabled.
2. **Movie video:** Runway and Manus adapters already exist behind the keyed Movie registry.
   Production validation now requires a supported provider key, model, HTTPS base URL, and
   the appropriate server-side credential/configuration, including Manus agent settings.
3. **Generic music:** Mubert and Stable Audio remain generic Music Studio adapters. Production
   validation now requires complete provider-specific configuration when `MusicGeneration` is
   enabled, but this does not activate soundtrack media submission.
4. **Direct video:** a real vendor schema, credentials, pricing, cancellation/retrieval
   semantics, and commercial terms are still required before any direct adapter can be
   selected for Movie.

## C. Business decisions required

- Approve a provider and commercial terms for Movie dialogue, including paid-user output
  rights, retention, attribution, voice consent, and supported Arabic/Kurdish quality.
- Select and contract an actual SFX/ambience provider or explicitly define a first-party
  import/library-only workflow.
- Decide whether soundtrack generation is a first-class durable Movie generation job or a
  reuse of Music Studio jobs. That decision determines ownership of output publication,
  retry/idempotency, provider operation status, and cue-version provenance.
- Approve customer charging and workspace-level cost controls separately from provider
  credential enablement. Customer charging remains disabled.

## D. Real-provider E2E validation still required

No real-provider validation was attempted in this wave. Before enablement, run an approved,
credentialed test against exactly one provider at a time and verify:

- authentication, quota/rate-limit behavior, bounded timeout, cancellation, and retry safety;
- actual audio/video MIME, byte size, duration, and output provenance;
- Arabic and Kurdish language/voice quality, including dialect acceptance criteria;
- provider-reported versus estimated cost and zero customer charge until billing approval;
- private storage publication, asset authorization, download retention, and incident-safe logs;
- stale-worker recovery and idempotency for asynchronous video/music operations.

## E. Optional or out-of-scope product enhancements

- Full NLE editing, waveform editing, stems, loudness mastering, multi-track automation,
  collaborative playback, and advanced transition authoring are product expansions, not safe
  provider-seam closures.
- Streaming voice, music callbacks, multi-output music, resumable provider retrieval, and
  native provider progress should be added only after a product requirement and an approved
  contract justify extending the current bounded interfaces.
